# تقرير مراجعة وتجهيز مشروع AlTayerERP

**تاريخ المراجعة:** 19 أغسطس 2026

**الفرع:** `chore/prepare-release-baseline`

**النطاق:** مراجعة خط الأساس الموجود في `master`، إصلاح بوابات الأمان والجودة ذات الأولوية، وإضافة تحقق قابل للتكرار.

## الملخص التنفيذي

تم تجهيز خط أساس أفضل للمشروع من الناحية الأمنية وقابلية التحقق. أزيل نص الاتصال الذي يحتوي بيانات اعتماد من `appsettings.json`، وأصبحت سياسة CORS مغلقة افتراضيًا ولا تسمح إلا بالأصول المعرفة في الإعدادات. أضيف ملف إعداد نموذجي ودليل عربي للتشغيل الآمن، كما أضيف مشروع اختبارات يثبت ثلاث قواعد أساسية في خدمة التحقق من السندات.

نجح بناء API والطبقات التابعة له، ونجحت الاختبارات الآلية الثلاثة محليًا باستخدام **.NET 8 SDK 8.0.130**. أما تطبيق Windows Forms فلم يُبنَ داخل بيئة Linux الحالية لأن أدوات Windows Desktop الخاصة بالـ SDK غير متاحة فيها؛ وقد أضيف له مسار بناء مستقل على عامل `windows-latest` في CI.

## نتائج التحقق

| الفحص | النتيجة | الملاحظات |
|---|---|---|
| `dotnet build AlTayerERP.API/AlTayerERP.API.csproj --configuration Release` | ناجح | صفر تحذيرات وصفر أخطاء |
| `dotnet test AlTayerERP.Tests/AlTayerERP.Tests.csproj --configuration Release` | ناجح | 3 ناجحة، 0 فاشلة، 0 متخطاة |
| `dotnet sln AlTayerERP.sln list` | ناجح | API وCore وDesktop وInfrastructure وTests موجودة |
| `git diff --check` | ناجح | لا توجد أخطاء مسافات أو تنسيق في الفروقات |
| بناء Windows Forms محليًا | غير منفذ | بيئة المراجعة Linux؛ مساره موجود في CI على Windows |
| تشغيل API ضد MySQL | غير منفذ | يتطلب قاعدة بيانات وبيانات اعتماد يوفرها مالك البيئة |

## الملفات المهمة

يجب ضبط الاتصال من خلال User Secrets أو متغير `ConnectionStrings__DefaultConnection` كما هو موضح في [دليل الأمان والتجهيز](SECURITY-AND-SETUP-AR.md). لا ينبغي إعادة إضافة كلمة مرور إلى `appsettings.json` أو إلى أي ملف متتبع.

ينفذ التحقق الآلي من خلال [ملف GitHub Actions](../.github/workflows/ci.yml)، بينما توجد اختبارات قواعد السندات في مشروع `AlTayerERP.Tests`. يجب تشغيل عامل Windows قبل اعتماد جاهزية تطبيق سطح المكتب، كما يجب تشغيل فحص `/api/health` بعد توفير MySQL فعلي.

## العناصر المتبقية قبل الإنتاج

هذه الحزمة لا تعني أن النظام أصبح إصدارًا إنتاجيًا كاملًا. ما زالت هناك حاجة إلى تشغيل اختبارات قبول كاملة للدخول والصلاحيات والتهيئة ودورة السند من الإنشاء حتى الترحيل وإلغاء الترحيل، وإضافة اختبارات تكامل على قاعدة MySQL نظيفة، وتوحيد سياسة Migrations وملفات SQL، وفرز طلبات الدمج المفتوحة وربطها بإصدارات محددة.

كما يجب **تدوير كلمة المرور القديمة** إذا كانت مستخدمة فعليًا في أي بيئة، لأن إزالة القيمة من الملف الحالي لا تحذفها من تاريخ Git. ويجب تنفيذ مراجعة مستقلة للصلاحيات وسجل التدقيق قبل النشر الخارجي.
