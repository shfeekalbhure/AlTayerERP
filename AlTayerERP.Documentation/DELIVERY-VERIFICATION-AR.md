# سجل التحقق من التسليم التشغيلي

**تاريخ الفحص:** 20 أغسطس 2026
**الفرع محل الفحص:** `agent/unified-phase1-screens`

## نتيجة خط الأساس

تم تثبيت .NET SDK 8 لتشغيل مشاريع الخادم والاختبارات، ثم شغّل الأمر التالي بنجاح:

```bash
dotnet test AlTayerERP.Tests/AlTayerERP.Tests.csproj -c Release
```

كانت النتيجة الابتدائية **19 اختباراً ناجحاً من 19** بلا اختبار متجاوز أو فاشل. وبعد تدقيق طبقات الخادم والعملاء وإضافة اختبارات الانحدار، كانت نتيجة التحقق الأخيرة عبر `scripts/verify-release.sh` هي **29 اختباراً ناجحاً من 29** بلا اختبار متجاوز أو فاشل. يغطي ذلك صحة استجابة الخادم، قواعد منع ترحيل السند، تحقق حقول السند، منع التكرار المالي، تسلسل حجز الأرقام، القرارات المتزامنة للاعتماد، تدوير Refresh Token، معالجة الاستثناءات الآمنة، وعقود عرض الخطأ والجلسة في MAUI وسطح المكتب، وعقد العرض المختصر للسند.

| المكوّن | حالة التحقق | النتيجة | التفسير |
|---|---|---|---|
| Core + Infrastructure + API | `dotnet build -c Release -warnaserror` | ناجح بلا تحذيرات | مشاريع الخادم المكتوبة لـ .NET 8 تُبنى بنجاح مع تحويل التحذيرات إلى أخطاء. |
| AlTayerERP.Tests | `scripts/verify-release.sh` | **29/29 ناجح** | اجتازت حزمة اختبارات الخادم وعقود الانحدار، بما فيها الاعتماد المتزامن، تدوير الجلسة، وتحويل الخطأ الآمن في العملاء، وعقد العرض المختصر للسند. |
| سطح المكتب WinForms | `dotnet build AlTayerERP.Desktop -c Release -p:EnableWindowsTargeting=true -warnaserror` | ناجح بلا تحذيرات | تحقق البناء المتقاطع من كود WinForms وموارده؛ يبقى التشغيل والتفاعل الفعليان على Windows إلزاميين. |
| MAUI Android | `dotnet build ...Mobile.Office... -c Release` | محجوب بيئياً | الهدف `net10.0-android` يحتاج حمولة MAUI مسجلة؛ بيئة Linux الحالية لم تسجل الحمولة لدى SDK رغم محاولة الاستعادة. |
| MySQL الإنتاج | غير منفذ عمداً | غير مختبر | يحظر تنفيذ أي ترحيل أو بيانات اختبار في الإنتاج. |

كشف بناء سطح المكتب المتقاطع 15 تحذير Nullable. عولجت التحذيرات ذات الأثر التنفيذي في طباعة المدن والمحافظات والحسابات والمستخدمين والسندات والمراجع الجغرافية، وفي تصفية صلاحيات المستخدم وتواقيع أحداث العملات. ثم أُعيد البناء مع `-warnaserror` وانتهى بلا تحذيرات؛ لم يتغير تخطيط عناصر المصمم أو عقد API.

> نجاح اختبارات SQLite يثبت صحة القيود العلائقية في طبقة EF، لكنه لا يغني عن اختبار التزامن والأقفال والترحيل على MySQL في بيئة اختبار معزولة.

## فحوصات إلزامية قبل القبول النهائي

يجب تنفيذ هذه الخطوات في جهاز Windows مع Visual Studio و.NET SDK/Workloads المطابقة قبل إصدار حزمة سطح المكتب أو Android:

1. بناء `AlTayerERP.sln` بوضع `Release` ثم تشغيل `dotnet test AlTayerERP.Tests/AlTayerERP.Tests.csproj -c Release`.
2. بناء `AlTayerERP.Mobile.Office` بوضع `Release` مع Android SDK، وتثبيت APK على جهاز ضمن شبكة الخادم الداخلية.
3. تطبيق ترحيل `20260820043000_AddIdempotencyRecords` أولاً على نسخة MySQL تجريبية ثم اختبار مفتاح `Idempotency-Key` المتكرر والمتعارض لسند القبض وطلب الصرف.
4. إجراء اختبار قبول يدوي كامل: دخول، شركة وفرع وسنة، طلب صرف وإرساله، ظهوره في الاعتماد، قرار مستخدم مختلف، إنشاء سند قبض، وإعادة المحاولة بعد قطع شبكة مصطنع.

لا يمنح هذا التقرير قبولاً نهائياً للإنتاج قبل تنفيذ الخطوات السابقة؛ لكنه يثبت أن طبقة الخادم والاختبارات القابلة للتشغيل في البيئة الحالية اجتازت خط الأساس.

|---|---|---|
| الاعتماد | لا يقبل طلب واحد قرارين متزامنين، ويعيد المسار المتأخر `409 Conflict`. | ناجح على SQLite علائقية. |
