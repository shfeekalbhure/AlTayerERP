# تقرير مراجعة الخبراء — AlTayerERP وتطبيق Mobile Office

**تاريخ المراجعة:** 20 أغسطس 2026
**الفرع المشمول:** `agent/unified-phase1-screens`
**النطاق:** واجهات API وتطبيق الجوال الأصلي `AlTayerERP.Mobile.Office` المبني بـ .NET MAUI. لا يشمل التقرير مشروع Expo المنفصل، ولا يتضمن أي تعديل مباشر لقاعدة بيانات الإنتاج.

## الخلاصة التنفيذية

ركزت المراجعة على أكثر المسارات حساسية تشغيلياً: تسجيل الدخول وإعداد عنوان الخادم، تحميل صلاحيات المكتب، طلبات الصرف، سندات القبض، وطلبات الاعتماد. أُصلحت ثلاث عيوب آمنة في تطبيق MAUI: كشف استجابة الخادم الخام عند تحميل صلاحيات المكتب، تكوين عنوان API غير صالح عند إدخال عنوان كامل مع منفذ، وكشف تفاصيل الشبكة واسم قاعدة البيانات في رسائل سند القبض.

> لا تزال سلامة ترقيم `PAYMENT_REQUEST` ومنع التكرار المالي مسؤولية خادم API وقاعدة البيانات؛ لا يعالجها التطبيق الجوال محلياً ولا ينبغي التحايل عليها من الواجهة.

| التصنيف | الحالة | النتيجة |
|---|---|---|
| حماية رسائل واجهة الجوال | تم الإصلاح | لم تعد شاشة المكتب تعرض نص استجابة API الخام. |
| صحة عنوان خادم Wi-Fi | تم الإصلاح | تقبل الواجهة عنواناً كاملاً أو عنوان مضيف، وتفصل المنفذ عن حقل العنوان. |
| رسائل سند القبض | تم الإصلاح | لا تعرض تفاصيل استثناء الشبكة أو اسم قاعدة البيانات للمستخدم. |
| ترقيم طلبات الصرف | قيد خادمي | يلزم فحص إعداد `PAYMENT_REQUEST` من مسؤول قاعدة البيانات. |
| منع تكرار الحفظ المالي | قيد معماري خادمي | يلزم تطبيق مفتاح عدم تكرار ومعالجة ذرية على API/قاعدة البيانات. |
| اختبار البناء والجهاز | مطلوب في Windows | لا تتوفر أدوات .NET أو MAUI في بيئة المراجعة الحالية. |

## الإصلاحات المنفذة

| المعرف | المجال | الخلل | المعالجة |
|---|---|---|---|
| MOB-SEC-01 | صلاحيات المكتب | كانت استجابة API الخام قد تظهر للمستخدم عند فشل تحميل صلاحيات الصفحة الرئيسية. | توحيد الفشل عبر `MobileApiErrorHandler.EnsureSuccess` في `MobileHomeService`. |
| MOB-CONN-01 | إعداد الاتصال | إدخال `http://172.16.5.82:5021` مع منفذ منفصل قد ينتج عنواناً غير صالح مكرراً للمنفذ. | تطبيع العنوان لاستخراج المضيف فقط، مع دعم IPv6، في `ApiClientConfiguration`. |
| MOB-SEC-02 | سند القبض | كانت رسالة تعذر الاتصال تحتوي تفاصيل استثناء الشبكة، وكانت قائمة فارغة تكشف اسم قاعدة بيانات داخل رسالة المستخدم. | استبدالها برسائل عربية قابلة للتنفيذ، مع الاحتفاظ بالاستثناء الداخلي للتشخيص. |

## نتائج المراجعة التي تحتاج عملاً خارج تطبيق الجوال

### ترقيم طلبات الصرف

إنشاء طلب صرف يعتمد على إعداد ترقيم مركزي من نوع `PAYMENT_REQUEST`. إذا كان الإعداد غائباً أو خارج الشركة/الفرع/السنة المالية، يتوقف الحفظ من الخادم كما هو مطلوب لحماية السجلات. المسار المسموح هو تنفيذ الاستعلام الآمن `Database/Scripts/20260820_diagnose_payment_request_numbering.sql` من قبل مسؤول قاعدة البيانات، ثم تطبيق المعالجة المعتمدة بعد النسخ الاحتياطي. لا ينفذ تطبيق الجوال أي تعديل للترقيم.

### منع تكرار العمليات المالية

قد يؤدي انقطاع الشبكة بعد إرسال طلب الحفظ إلى عدم يقين المستخدم حول نجاح العملية. الحماية الكاملة تتطلب دعماً من API لمفتاح عدم تكرار مخزَّن ومعاملة قاعدة بيانات ذرية؛ إعادة المحاولة من الجوال وحدها ليست ضماناً كافياً. يجب إضافة هذه الحماية في الخادم قبل اعتماد إعادة المحاولة التلقائية لطلبات الصرف وسندات القبض.

## التحقق المنفذ والقيود

تم تنفيذ `git diff --check` ونجح بلا أخطاء مسافات أو رقع غير سليمة. لم يكن ممكناً تشغيل `dotnet build` أو اختبارات `AlTayerERP.Tests` لأن بيئة المراجعة لا تحتوي `dotnet` أو `msbuild` أو `mono`. هذا **قيد بيئة مراجعة** وليس نتيجة نجاح أو فشل للبناء.

## خطة اختبار القبول على Windows

| التدفق | الإجراء | معيار القبول |
|---|---|---|
| عنوان الاتصال | أدخل المضيف فقط، ثم عنواناً كاملاً مع منفذ، ثم IPv6 عند توفره. | لا يظهر عنوان مكرر للمنفذ، وتصل طلبات الصحة إلى API الصحيح. |
| صلاحيات المكتب | سجل الدخول بمستخدم لا يملك صلاحيات الصفحة الرئيسية أو أوقف API مؤقتاً في بيئة اختبار. | تظهر رسالة آمنة ومفهومة، ولا يظهر JSON أو HTML أو تفاصيل خادم خام. |
| سند قبض | اقطع الشبكة أثناء تحميل المراجع، ثم أعدها. | تظهر رسالة اتصال عامة قابلة للتنفيذ دون عنوان داخلي أو اسم قاعدة بيانات. |
| طلب صرف | أنشئ طلباً بحساب اختبار. | يُحفظ برقم مركزي واحد، أو تظهر رسالة ترقيم واضحة إذا كان الإعداد ناقصاً. |
| اعتماد | حمّل طلباً، وجرّب الاعتماد الذاتي والرفض بلا سبب إن كانت السياسة تمنعهما. | يفرض الخادم قواعد الانتقال والسياسة، وتظهر الرسالة العربية المناسبة. |
| البناء | نفذ `dotnet test AlTayerERP.Tests/AlTayerERP.Tests.csproj` ثم بناء MAUI من Visual Studio على Windows. | نجاح الاختبارات والبناء دون أخطاء أو تحذيرات جديدة مرتبطة بهذه الملفات. |

## قرار الجاهزية

الإصلاحات الحالية جاهزة للمراجعة على فرع `agent/unified-phase1-screens` بعد تنفيذ اختبار Windows والجهاز. لا تُصنّف العمليات المالية كجاهزة للإطلاق الإنتاجي النهائي قبل تحقق مسؤول الخادم من الترقيم، وإقرار آلية منع التكرار من طرف API، واجتياز خطة القبول أعلاه.
