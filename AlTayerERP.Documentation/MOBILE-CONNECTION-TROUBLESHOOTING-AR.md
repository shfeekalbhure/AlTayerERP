# تشخيص اتصال Mobile.Office بخادم AlTayerERP API

## النتيجة من شاشة الهاتف

تظهر الشاشة أن التطبيق يحاول الوصول إلى الخادم عبر العنوان `192.168.1.10` والمنفذ `5021`، ثم يفشل فحص `api/health`. لذلك لا تصل الشاشة إلى مرحلة تحميل الشركات؛ رسالة قائمة الشركات هي نتيجة لاحقة لفشل الاتصال وليست دليلًا على أن جدول الشركات فارغ.

## الفحص الصحيح على جهاز الخادم

شغّل مشروع `AlTayerERP.API` باستخدام ملف تعريف HTTP الذي يستمع على `http://0.0.0.0:5021`، وليس تشغيل HTTPS المحلي فقط. بعد ذلك افتح من متصفح جهاز الخادم:

```text
http://localhost:5021/api/health
```

يجب أن تكون الاستجابة HTTP 200 وتحتوي على `api: "ready"` و`database: "ready"`. إذا كانت الاستجابة HTTP 503، فقد وصل الهاتف إلى API لكن API لا يستطيع الاتصال بقاعدة MySQL؛ عالج `ConnectionStrings:DefaultConnection` وقاعدة البيانات أولًا.

## الفحص من الهاتف أو من جهاز آخر على الشبكة

استبدل `192.168.1.10` بعنوان IPv4 الفعلي لجهاز الخادم، ثم افتح:

```text
http://192.168.1.10:5021/api/health
```

إذا لم يفتح العنوان، فالمشكلة في التشغيل أو عنوان IP أو الشبكة أو جدار Windows الناري. يجب أن يكون الهاتف وجهاز الخادم على شبكة Wi‑Fi نفسها، وألا تكون الشبكة في وضع عزل العملاء (AP/Client Isolation). يجب أيضًا السماح باتصالات TCP الواردة على المنفذ `5021` في جدار الجهاز المضيف.

## اتصال USB

عنوان `127.0.0.1` داخل تطبيق Android يعني الهاتف نفسه، وليس جهاز الكمبيوتر. لذلك يعمل وضع USB فقط إذا كان هناك USB reverse port forwarding، مثل:

```text
adb reverse tcp:5021 tcp:5021
```

بعد تشغيل الأمر، شغّل API على جهاز الكمبيوتر ثم اختبر `http://127.0.0.1:5021/api/health` من التطبيق. إذا لم تستخدم `adb reverse`، اختر Wi‑Fi وأدخل عنوان IP الخاص بجهاز الخادم.

## ما تم تحسينه في التطبيق

تم تحديث رسائل التشخيص لتفرق بين رفض الاتصال، انتهاء المهلة، عنوان DNS/IP غير الصحيح، والوصول إلى API مع عدم جاهزية قاعدة البيانات. كما تعرض شاشة إعداد الاتصال العنوان الذي تم اختباره فعليًا. صلاحية Android للإنترنت والسماح باتصالات HTTP المحلي موجودان أصلًا في `Platforms/Android/AndroidManifest.xml`، لذلك لا يُرجح أن يكون `usesCleartextTraffic` هو سبب الصورة الحالية.

## ترتيب التشخيص العملي

| الترتيب | الاختبار | النتيجة المطلوبة |
|---|---|---|
| 1 | تشغيل `AlTayerERP.API` بملف HTTP | الاستماع على `0.0.0.0:5021` |
| 2 | فتح `/api/health` على جهاز الخادم | HTTP 200 و`api/database = ready` |
| 3 | فتح `/api/health` من الهاتف | يجب أن ينجح عبر نفس عنوان IP والمنفذ |
| 4 | مراجعة جدار Windows والشبكة | السماح بـTCP 5021 وعدم وجود عزل Wi‑Fi |
| 5 | إعادة اختبار الاتصال من التطبيق | تظهر رسالة نجاح ثم قائمة الشركات |

إذا نجح `/api/health` من الهاتف ولم تظهر الشركات، عندها فقط ننتقل إلى فحص شروط `LoginCompanies` و`Show_In_Login` في قاعدة البيانات. أما في الحالة المصورة، فالأولوية هي الاتصال بالخادم.
