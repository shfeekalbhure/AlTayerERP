# قبول محرك القيود والترحيل — المرحلة الأولى

تنفذ هذه الاختبارات على نسخة اختبار من قاعدة `altayer_erp_db` فقط، ولا تستخدم Triggers لإنشاء القيود أو لتغيير حالة السندات.

| الرمز | الحالة | النتيجة المطلوبة |
|---|---|---|
| VPE-01 | حفظ سند متوازن | ينشأ كمعلق/مسودة، بلا قيد يومية وبلا أثر رسمي في التقارير. |
| VPE-02 | حفظ سند غير متوازن | رفض من الـBackend ولا يُحفظ الرأس أو التفاصيل. |
| VPE-03 | مراجعة ثم اعتماد | تسجل العملية والمستخدم والوقت والجهاز في سجل حركات السند. |
| VPE-04 | ترحيل سند ضمن فترة مفتوحة | ينشأ قيد واحد فقط مطابق لسطور السند؛ تتساوى المدين والدائن؛ يربط `Journal_Entry_ID`. |
| VPE-05 | ترحيل السند نفسه مرتين | النداء الثاني مرفوض، ولا ينشأ قيد ثانٍ. |
| VPE-06 | ترحيل بفترة مغلقة أو بلا فترة تغطي التاريخ | رفض من الـBackend. |
| VPE-07 | ترحيل مع حساب أو عملة موقوفة | رفض من الـBackend. |
| VPE-08 | فك ترحيل بلا سبب | رفض. |
| VPE-09 | فك ترحيل بسبب صحيح | يلغي القيد منطقياً، يعيد السند إلى `PENDING`، ويحفظ السبب والمستخدم والتاريخ. |
| VPE-10 | تعديل أو حذف سند مرحل | رفض من الـBackend. |
| VPE-11 | مستخدم بلا صلاحية `Approve/Post/Unapprove` | استجابة `403` ولا تتغير أي حالة. |
| VPE-12 | سند صرف وقيد يومية | تطبق القواعد نفسها، مع صلاحية الشاشة المختصة عند استكمال واجهاتها. |

## تحقق قاعدة البيانات بعد VPE-04

- صف واحد فقط في `journal_entry_headers` حيث `Source_Voucher_ID = Voucher_ID`.
- مجموع `Debit_Amount` يساوي مجموع `Credit_Amount` في `journal_entry_details`.
- لا يوجد حذف مادي للسند أو القيد عند فك الترحيل.
- تظهر عمليات `CREATE/REVIEW/APPROVE/POST/UNPOST` في `voucher_action_logs` وسجل التدقيق المركزي.
