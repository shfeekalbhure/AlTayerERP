# قبول بيانات الحسابات المرجعية — المرحلة الأولى

## نطاق الاختبار

هذه الحالات تتحقق من دليل الحسابات ومراكز التكلفة والعملات وأسعار الصرف والصناديق والحسابات البنكية. جميع الطلبات تحمل JWT صالحاً وتُقرأ الشركة والفرع والمستخدم من `ServerSession` فقط.

| الحالة | الإجراء | النتيجة المقبولة |
|---|---|---|
| MD-01 | مستخدم بلا صلاحية `Currencies/View` يستدعي العملات | `403 Forbidden` — Default Deny |
| MD-02 | يرسل العميل `Company_ID` لشركة أخرى عند حفظ عملة | يحفظ الخادم فقط ضمن شركة الجلسة |
| MD-03 | إنشاء عملتين محليتين | تبقى عملة محلية واحدة؛ الثانية تلغي العلامة السابقة داخل Transaction |
| MD-04 | إيقاف العملة المحلية | `400` حتى تعيين بديل |
| MD-05 | سعر صرف لعملة غير فعالة أو خارج الحد | `400` ولا ينشأ سجل |
| MD-06 | تكرار (شركة، عملة، تاريخ سعر الصرف) | `409 Conflict` |
| MD-07 | إنشاء حساب تجميعي قابل للترحيل | `400` |
| MD-08 | نقل حساب تحت أحد أبنائه | `400` ولا تنشأ حلقة |
| MD-09 | إيقاف حساب له حركة قيد | `400`؛ لا حذف مادي |
| MD-10 | مركز تكلفة أب قابل للترحيل | لا يسمح بإضافة ابن تحته |
| MD-11 | إعادة ربط مركز تكلفة تحت أحد أبنائه | `400` |
| MD-12 | إنشاء صندوق | ينشأ حساب GL غير قابل للإدخال اليدوي والصندوق في Transaction واحدة |
| MD-13 | صندوق أو حساب بنك خارج الشركة/الفرع في الجلسة | `404` ولا يكشف بيانات |
| MD-14 | عملة صندوق أو بنك غير فعالة | `400` |
| MD-15 | إيقاف صندوق له حركة قيد | `400`؛ السجل والحساب محفوظان |
| MD-16 | إنشاء/تعديل/إيقاف أي سجل | يسجل `Audit_Logs` المستخدم والجلسة والقيم والعملية |

## اختبارات التزامن

1. نفّذ 20 طلب إنشاء متزامن لصناديق في الشركة نفسها، ثم تحقق من عدم تكرار `CashBox_Code` أو `Account_Code`.
2. نفّذ إنشاء مراكز تكلفة متزامناً تحت الأب نفسه، ثم تحقق من عدم تكرار `Center_Code`.
3. تُستكمل هذه الاختبارات على نسخة اختبار من قاعدة `altayer_erp_db` فقط، ولا تستخدم Triggers لإنشاء القيود أو الأرقام.
