# قبول الجزء 31 — السندات وطلب الصرف

## سند القبض
- العملة المحلية: الأجنبي صفر وسعر الصرف 1 ومقفلاهما؛ في الأجنبية المحلي = الأجنبي × السعر.
- الصندوق/البنك مدين والتفاصيل دائنة؛ الحساب/العملة/المركز/المرجع لكل سطر.
- الترحيل يرفض خارج نطاق الشركة/الفرع/السنة أو فترة مغلقة أو دون اعتماد.

## سند الصرف
- الصندوق/البنك دائن والتفاصيل مدينة، مع سطر مستقل لكل عملة ومركز ومرجع.
- رفض أي سطر مدين/دائن معاً أو عملة موقوفة أو عدم توازن.
- لا تعديل أو حذف بعد الترحيل؛ فك الترحيل بسبب إلزامي.

## القيد اليومي
- سطران على الأقل متوازنان؛ كل سطر يملك الحساب والعملة والسعر والمركز والمرجع.
- لا يمر الترحيل إلا من Backend وبعد المراجعة والاعتماد والفترة المفتوحة.

## طلب الصرف
- DRAFT → PENDING_REVIEW → PENDING_APPROVAL → APPROVED/REJECTED/RETURNED حصراً.
- لا يوجد في الشاشة أو API أي post/unpost أو إنشاء قيد.
- لا ينشأ سند صرف إلا من APPROVED مرة واحدة؛ يتوقف عند تجاوز السقف المالي أو المبلغ المعتمد.
- اختبار صلاحيات: غياب View/Add/Edit/Approve/Unapprove/Delete يعيد 403؛ ومدير النظام لا يتجاوز التفويض الصريح.
- المرفق يحفظ خارج قاعدة البيانات، مع metadata محكومة بالشركة/الفرع/السنة وتدقيق Upload/Delete.

## حالات قبول إغلاق طلب الصرف

### PR-01 — تهيئة الترقيم
1. شغّل `Database/Scripts/20260724_add_payment_requests.sql` مرتين على قاعدة الاختبار.
2. تحقق أن الاستعلام الأخير يعيد إعداداً نشطاً واحداً على الأقل للكود `PAYMENT_REQUEST`.
3. أنشئ طلب صرف جديد.

**النتيجة المتوقعة:** لا يفشل السكربت عند التشغيل الثاني، ويصدر رقم يبدأ بـ `PRQ` ويشمل نطاق الشركة والفرع والسنة حسب خدمة الترقيم المركزية.

**دليل القبول:** سجل SQL، رقم الطلب الناتج، وسجل `NUMBER_RESERVED` في التدقيق.

### PR-02 — حفظ المسودة وتعديلها
1. اختر مستفيداً وطريقة سداد وفترة مفتوحة.
2. أضف سطراً محلياً صالحاً وسطر عملة أجنبية يكون فيه المحلي = الأجنبي × سعر الصرف.
3. احفظ الطلب كمسودة، ثم عدّل الوصف والمبالغ واحفظ مجدداً.

**النتيجة المتوقعة:** الحفظ والتعديل ناجحان والحالة `DRAFT`، مع منع الحساب أو مركز التكلفة غير النشط أو غير القابل للترحيل.

**دليل القبول:** استجابة API، بيانات الجدولين `payment_requests` و`payment_request_lines`، وسجلا CREATE وUPDATE.

### PR-03 — دورة المراجعة والاعتماد
1. أرسل المسودة للمراجعة.
2. نفّذ المراجعة بسبب إلزامي.
3. أعد الطلب بسبب، وعدّله ثم أعد إرساله.
4. راجعه واعتمده بسبب إلزامي.

**النتيجة المتوقعة:** لا يسمح الخادم بأي انتقال خارج التسلسل المعتمد، وتسجل الحالة والسبب والمستخدم والوقت في التدقيق.

**دليل القبول:** صور الحالات المتتابعة واستجابات API وسجلات SUBMIT وREVIEW وRETURN وAPPROVE.

### PR-04 — المرفقات
1. في حالة `DRAFT` أضف مرفقاً أقل من 20MB ثم نزّله وافتحه.
2. احذف المرفق مع سبب.
3. أضف مرفقاً جديداً ثم أرسل الطلب للمراجعة.
4. حاول إضافة أو حذف مرفق بعد الإرسال.

**النتيجة المتوقعة:** الإضافة والتنزيل والحذف تعمل في `DRAFT` أو `RETURNED` فقط، وبعد الإرسال يعيد الخادم 409. تستخدم المرفقات صلاحيات شاشة `PaymentRequest` ولا تعتمد على كود شاشة مستقل.

**دليل القبول:** الملف المفتوح، استجابة 409، وسجلا UPLOAD وDELETE.

### PR-05 — إنشاء سند الصرف المرتبط
1. افتح طلباً معتمداً واختر صندوقاً أو بنكاً دائناً صالحاً.
2. أنشئ سند الصرف.
3. أعد تنفيذ الإنشاء لنفس الطلب.

**النتيجة المتوقعة:** ينشأ سند واحد متوازن فقط، يحفظ `Payment_Voucher_ID` في الطلب، والمحاولة الثانية تعيد 409 ولا تنشئ حركة سقف مالي إضافية.

**دليل القبول:** رقم السند، القيد المتوازن، رابط الطلب بالسند، حركة السقف المالي، وسجل CREATE_PAYMENT_VOUCHER.

### PR-06 — حدود الصلاحيات والسياق
1. اختبر مستخدماً بلا View، ثم View فقط، ثم Edit دون Approve.
2. غيّر معرف الشركة أو الفرع أو السنة في طلب العميل يدوياً.

**النتيجة المتوقعة:** يعيد الخادم 403 للعمليات غير المصرح بها، ولا يمكن تجاوز شركة/فرع/سنة الجلسة.

**دليل القبول:** حسابات الاختبار، رموز الاستجابة، وعدم ظهور أو تعديل سجلات خارج السياق.
