# مصفوفة اختبار قبول الجوال — طلب الصرف على القاعدة النظيفة

**المستودع:** `shfeekalbhure/AlTayerERP`
**فرع التنفيذ:** `agent/mobile-payment-request-clean-db-integration`
**قاعدة الاختبار الوحيدة:** `altayer_erp_db_clean`

## 1. القيود وبوابة الإغلاق

ممنوع: الاتصال بـ`altayer_erp_db`، تنفيذ SQL يدوي، إعادة `Baseline_Phase1`، تعديل مخطط القاعدة، الدمج إلى `master`، أو دمج PR #14 قبل نجاح UAT.

لا تغلق الحزمة تسليميًا إلا بعد نجاح كل حالة حرجة أدناه وإرفاق دليلها؛ ويتضمن ذلك فصل الواجبات، عدم وجود `409` وهمي، إنشاء سند صرف واحد فقط، صحة الترقيمين، عزل السياق، وعدم الانحدار لسندي القبض والصرف.

## 2. المستخدمون المعتمدون

| المستخدم | الدور في الاختبار | الصلاحيات الدنيا |
|---|---|---|
| U1 | منشئ طلب الصرف | `PaymentRequest.View`, `PaymentRequest.Add`, `PaymentRequest.Edit` |
| U2 | مراجع مستقل | `PaymentRequest.View`, `PaymentRequest.Approve` |
| U3 | معتمد مستقل | `PaymentRequest.View`, `PaymentRequest.Approve`, `PaymentRequest.Unapprove` |
| U4 | منشئ سند الصرف | `PaymentRequest.View`, `PaymentVoucher.Add` |
| U5 | اختبار سلبي | بلا صلاحية كافية |

**قاعدة فصل الواجبات:** يمنع استخدام مستخدم واحد لجميع المراحل.

## 3. طريقة التوثيق

في كل صف: يملأ المنفذ **النتيجة الفعلية** و**الحالة** (`ناجح`/`فاشل`/`محجوب`) ومرجع **الدليل** (صورة/فيديو/استجابة API) ومرجع **سجل التدقيق**. لا تكتب Token أو كلمة مرور أو Connection String في الدليل.
