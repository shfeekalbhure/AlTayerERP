# تقرير الجاهزية التشغيلية — AlTayerERP Mobile Office

**تاريخ المراجعة:** 20 أغسطس 2026  
**نطاق التطبيق:** الدخول واختيار الشركة، الاتصال بخادم AlTayerERP، طلبات الصرف، سندات القبض، طلبات الاعتماد، ومركز التشخيص.  
**مبدأ الحماية:** لا يتصل التطبيق مباشرة بقاعدة البيانات ولا ينفذ أي تعديل على بيئة الإنتاج.

## الحالة المختصرة

| المجال | الحالة | الدليل أو القيد |
|---|---|---|
| بناء TypeScript | مكتمل | `pnpm check` يمر بلا أخطاء. |
| الاختبارات الآلية | مكتمل | 8 اختبارات ناجحة؛ اختبار تسجيل الخروج الموروث متجاوز عمداً. |
| فحص القواعد البرمجية | مكتمل | `pnpm lint` بلا أخطاء أو تحذيرات من الشفرة. يبقى تحذير إعداد Node غير مؤثر في زمن التشغيل. |
| أخطاء الحقول ومعرّف المتابعة | مكتمل | يقرأ التطبيق أخطاء الحقول، رمز الخطأ، و`CorrelationId`/`TraceId` من استجابة API. |
| منع تكرار الحفظ المالي | مكتمل من طرف العميل | يرسل التطبيق `Idempotency-Key` مع إنشاء طلب الصرف وسند القبض؛ يحتاج الخادم احترام المفتاح لتحقيق حماية شاملة. |
| فحص الخادم الحقيقي من بيئة البناء | غير متاح | فشل اتصال غير مدمّر إلى `172.16.5.82:5021/api/health` بالمهلة؛ عنوان LAN خاص ولا يمكن الوصول إليه من بيئة البناء السحابية. |
| اختبار الهاتف على Wi-Fi المؤسسة | مطلوب | يجب تنفيذه من هاتف داخل نفس الشبكة أو عبر مسار VPN معتمد. |
| ترقيم `PAYMENT_REQUEST` | عائق خادمي معروف | لا يمكن للجوال إثباته أو إصلاحه؛ يلزم فحص قاعدة بيانات API وإعداد الترقيم من مسؤول معتمد. |

## خطوات التشغيل على الهاتف

1. ثبّت النسخة من خلال قناة النشر المعتمدة، ثم افتح **إعداد الاتصال** قبل محاولة الدخول.
2. أدخل عنوان الخادم المحلي: `172.16.5.82` والمنفذ `5021`. إذا تغير العنوان عبر DHCP، أدخل عنوان Wi-Fi الحالي لجهاز الخادم بدلاً منه.
3. اضغط **اختبار الاتصال**. يجب أن يستجيب المسار `http://<host>:<port>/api/health` بحالة API وقاعدة بيانات سليمتين.
4. افتح شاشة الدخول واضغط **إعادة تحميل الشركات من الخادم**. لا تستخدم قائمة فارغة كدليل على عدم وجود شركات؛ افتح مركز التشخيص أولاً عند الفشل.
5. اختر الشركة ثم أدخل اسم المستخدم وكلمة المرور. يحفظ التطبيق رمز الجلسة في التخزين الآمن للجهاز فقط.
6. نفّذ اختباراً محدوداً على بيانات تدريبية أو حساب اختبار قبل استخدام أي حفظ مالي في بيئة الإنتاج.

## معالجة عائق ترقيم طلبات الصرف

> لا ينشئ تطبيق الجوال أرقام طلبات محلياً، ولا ينبغي تعديل الرقم يدوياً للتغلب على الخطأ.

عند ظهور خطأ يشير إلى `PAYMENT_REQUEST` أو عدم وجود إعداد ترقيم، افتح **مركز التشخيص** من رسالة الخطأ. ثم يتولى مسؤول الخادم الخطوات التالية خارج التطبيق:

1. ينفذ الاستعلام التشخيصي للقراءة فقط: `Database/Scripts/20260820_diagnose_payment_request_numbering.sql`.
2. يراجع الشركة والفرع والسنة المالية وحالة إعداد الترقيم المرتبط بـ `PAYMENT_REQUEST`.
3. بعد أخذ نسخة احتياطية وموافقة تشغيلية، يطبق السكربت المنظم الموجود في المستودع عند الحاجة: `Database/Scripts/20260724_add_payment_requests.sql`.
4. يعيد اختبار `POST api/payment-requests` بحساب اختبار، ثم يعيد المستخدم تحديث القائمة من التطبيق.

لا ينفذ أي من هذه الخطوات تلقائياً من التطبيق، ولا ينبغي تنفيذها مباشرة على الإنتاج دون مراجعة مسؤول قاعدة البيانات ومالك النظام.

## مصفوفة اختبار الجهاز المطلوبة

| التدفق | خطوات القبول | النتيجة المتوقعة |
|---|---|---|
| الاتصال | تعديل العنوان والمنفذ ثم اختبار الاتصال | رسالة نجاح أو وصف عربي قابل للتنفيذ لفشل الشبكة. |
| الدخول والشركات | تحميل الشركات ثم اختيار شركة وتسجيل الدخول | ظهور الشركات من `api/Auth/LoginCompanies` والدخول بعد اختيار الفرع والسنة من الخادم. |
| انقطاع الشبكة | أوقف Wi-Fi قبل تحديث قائمة أو حفظ | رسالة مهلة/وصول عربية، وعدم تكرار إنشاء العملية تلقائياً. |
| طلب الصرف | حفظ مسودة اختبار ثم إرسالها | رقم مركزي من API، أو رسالة ترقيم واضحة مع انتقال لمركز التشخيص. |
| سند القبض | تحميل المراجع ثم حفظ سند اختبار | تحميل المراجع من API وحفظ السند أو إظهار أخطاء الحقول ورد الخادم. |
| الاعتماد | افتح طلباً معلّقاً، ابدأ المراجعة، ثم اعتمد/ارفض | لا تظهر رسالة نجاح إلا بعد مزامنة القرار مع `api/approval-requests/{id}/{action}`. |
| استعادة الجلسة | أغلق التطبيق وافتحه بعد انتهاء الرمز | حذف الجلسة غير الصالحة وطلب دخول جديد بدلاً من تنفيذ عملية بصلاحية منتهية. |

## حدود الجاهزية وقرار التسليم

التطبيق **جاهز للمراجعة التشغيلية على هاتف متصل بشبكة الخادم** من ناحية البناء، العقود البرمجية، رسائل الأخطاء، والتدفقات الأساسية. لا تُعتبر الجاهزية نهائية للاستخدام المالي الإنتاجي قبل اجتياز مصفوفة اختبار الجهاز أعلاه وحل إعداد ترقيم `PAYMENT_REQUEST` على الخادم عند ظهوره.

لم يُدمج أي تعديل في فرع `master` لمستودع AlTayerERP، ولم تُعدّل قاعدة بيانات إنتاجية ضمن هذه المراجعة.
