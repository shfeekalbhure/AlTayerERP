# قبول واختبار المرحلة الأولى — من الدخول إلى سند القبض

## 1. قبل التشغيل

نفذ سكربتات قاعدة البيانات بالترتيب التالي:

1. `20260721_Seed_Phase1_System_Screens.sql`
2. `20260721_Create_Settings_And_Resource_Permissions.sql`
3. `20260721_Fix_Setting_Scope_Value_History.sql`
4. `20260721_Seed_Phase1_Settings.sql`

ثم اضبط مفتاح JWT خارج المستودع:

```
Jwt__SigningKey=<مفتاح عشوائي لا يقل عن 32 حرفاً>
Jwt__Issuer=AlTayerERP.API
Jwt__Audience=AlTayerERP.Desktop
```

## 2. اختبار البناء

- افتح الحل من فرع `agent/session-permissions-foundation`.
- نفذ Restore للحزم ثم Rebuild Solution.
- النتيجة المطلوبة: لا أخطاء بناء، ولا تعارض لملف موارد سند القبض.
- شغل API ثم تطبيق سطح المكتب.

| دخول بكلمة مرور خاطئة | إدخال كلمة مرور غير صحيحة | رفض الدخول دون كشف السبب التفصيلي |

## 4. اختبار الإعدادات

1. افتح **إدارة الإعدادات** كمدير نظام.
2. اختر `ReceiptVoucher.RequiresApproval`.
3. أضف قيمة `false` للنطاق `BRANCH` ومعرّف الفرع الحالي.
4. أنشئ سند قبض جديد.
5. النتيجة المطلوبة: السند لا يتطلب اعتماداً.
6. أضف قيمة أحدث `true` للنطاق نفسه.
7. النتيجة المطلوبة: القيمة السابقة تصبح معطلة، وتبقى في السجل، والسند الجديد يتطلب اعتماداً.
8. لإعداد حساس، اترك سبب التغيير فارغاً.
9. النتيجة المطلوبة: يرفض الخادم الحفظ.

## 6. اختبار الاستثناءات الدقيقة للمستخدم

1. من شاشة **صلاحيات المستخدم الدقيقة** اختر مستخدماً وشاشة سند القبض.
2. اجعل تنفيذ `POST` على **منع**، مع بقاء دور المستخدم مخولاً بالترحيل.
3. أعد تسجيل دخول المستخدم ثم افتح سنداً مراجعاً ومعتمداً.
4. النتيجة المطلوبة: زر الترحيل غير متاح، ويعيد الخادم `403` عند إرسال طلب مباشر.
5. اجعل رؤية `Amount` على **منع**.
6. النتيجة المطلوبة: الحقل لا يظهر ولا يمكن الوصول إليه بلوحة المفاتيح.
7. افحص جدول `audit_logs`.
8. النتيجة المطلوبة: يوجد سجل لتغيير الاستثناء مع المستخدم والفرع والوقت.

## 7. اختبار حفظ سند القبض

1. افتح سند جديد.
2. اختر الصندوق والعملة والطرف وادخل البيان والمبلغ.
3. أضف سطر الصندوق وسطر الحساب المقابل.
4. تأكد أن إجمالي المدين يساوي إجمالي الدائن.
5. احفظ.

النتائج المطلوبة:

- رقم سند رسمي من إعدادات الترقيم.
- رأس السند وتفاصيله تحفظ داخل معاملة واحدة.
- العملة المحلية تجعل المبلغ الأجنبي صفراً.
- العملة الأجنبية تحسب المحلي = الأجنبي × سعر الصرف.
- رفض الحفظ عند عدم توازن السند أو عند غياب الصندوق أو التفاصيل.
- رفض الحفظ عند عدم تطابق حساب سطر الصندوق مع رأس السند.
- رفض الحفظ عند عدم تطابق عملة أو مبلغ سطر الصندوق مع رأس السند.
- رفض الحفظ عند اختيار طريقة سداد غير نشطة أو عند ترك مرجع إلزامي فارغاً.

## 8. اختبار دورة المراجعة والاعتماد والترحيل

1. احفظ سنداً يتطلب اعتماداً.
2. نفذ **تمت المراجعة** من مستخدم مصرح.
3. اعتمد السند من مستخدم مختلف عن المنشئ عند تفعيل منع اعتماد المنشئ.
4. رحل السند.
5. استعرض القيد من السند.
6. نفذ فك الترحيل مع سبب.
7. ألغ الاعتماد مع سبب عند الحاجة.

النتائج المطلوبة:

- يمنع الاعتماد قبل المراجعة.
- يمنع اعتماد منشئ السند عندما يكون الإعداد مفعلاً.
- يمنع الترحيل قبل المراجعة والاعتماد المطلوب.
- ينشأ قيد محاسبي متوازن عند الترحيل.
- يسجل كل إجراء في سجل الحركات.
- لا يقبل فك الترحيل بلا سبب عند تفعيل الإعداد.
- عند تعطيل إلزام السبب، يحفظ الخادم سبباً تدقيقياً تلقائياً.

## 9. اختبار الحماية

- أرسل طلباً بدون Bearer Token إلى `FinancialVoucher`.
  - النتيجة: 401.
- أرسل طلب مراجعة أو ترحيل لمستخدم لا يملك الإجراء.
  - النتيجة: 403.
- حاول تمرير User_ID مختلفاً في جسم طلب المراجعة أو الترحيل.
  - النتيجة: يعتمد الخادم هوية الرمز فقط.
- ابحث أو افتح سنداً من فرع أو سنة أخرى.
  - النتيجة: لا يظهر السند ولا تنفذ عليه عملية.
- حاول الحذف أو التعديل بلا صلاحية.
  - النتيجة: 403.
