# AlTayerERP — كراسة التنفيذ المختصرة للمرحلة الأولى

## 1. حالة الوثيقة

- الحالة: معتمدة للتنفيذ.
- نطاق المرحلة: من الإقلاع والاتصال وتسجيل الدخول حتى إغلاق سند القبض وترحيله وطباعته وتدقيقه.
- أسلوب العمل: تطوير الموجود السليم، استكمال الناقص، تصحيح الخطر، ثم إضافة الجديد حسب الأولوية.
- الفرع التنفيذي: `agent/phase1-p0-baseline-hardening`.
- الفرع المستهدف: `master`.

## 2. قواعد ملزمة

1. لا يعاد بناء النظام من الصفر.
2. لا يعدل مخطط الإنتاج يدوياً؛ تستخدم Migrations مرقمة ومجربة.
3. لا تصل واجهة WinForms مباشرة إلى قاعدة بيانات الخادم؛ تمر عمليات الأعمال عبر API.
4. لا توضع كلمات مرور أو نصوص اتصال سرية في المستودع.
5. لا توجد قوائم تشغيلية ثابتة داخل شاشة سند القبض؛ تستخدم البيانات المرجعية أو الثوابت المحمية.
6. لا يرحل السند إلا داخل معاملة واحدة تنشئ قيداً واحداً متوازناً وقابلاً للتتبع.
7. لا يعتمد المنشئ سندَه عندما تفرض سياسة فصل الواجبات ذلك.
8. لا يتجاوز المستخدم نطاق شركته أو فرعه أو صندوقه.
9. لا تعتبر الشاشة مكتملة قبل الاختبارات والتدقيق وقياس الأداء وقبول المستخدم.
10. لا يبدأ سند الصرف أو الشحن قبل اجتياز سند القبض بوابة القبول.

## 3. الأولويات

### P0 — حرج للمرحلة الأولى

- تثبيت تشغيل API وقاعدة البيانات ومعالجة الأخطاء وفحوصات الصحة.
- الاتصال والدخول والجلسة والشركة والفرع والسنة والفترة.
- المستخدمون والأدوار والصلاحيات ونطاق البيانات وسجل التدقيق.
- كتالوج النظام ومركز البيانات المرجعية.
- أنواع الحسابات وأنواع السندات وطرق الدفع والترقيم.
- العملات وأسعار الصرف وشجرة الحسابات ومراكز التكلفة.
- البنوك والحسابات البنكية والصناديق وربط المستخدم ووردية الصندوق.
- الأطراف بالنموذج الموحد `Parties + PartyTypes + PartyTypeLinks`.
- محرك السندات المالي المشترك.
- إغلاق سند القبض: حفظ، بحث، تعديل، مراجعة، اعتماد، ترحيل، قيد، طباعة، فك ترحيل وتدقيق.

### P1 — بعد إغلاق P0

- مساحة العمل الموحدة والتبويبات والمفضلة والاختصارات.
- البحث الموحد وصندوق الموافقات والسجل الزمني وقوالب الطباعة.
- تحسينات الأداء والتقارير الرقابية ولوحة المتابعة.

### P2 — المرحلة التالية

- سند الصرف والقيد اليومي.
- أنواع الشحن والبوالص والأصناف والوحدات والرحلات والتسليم.

## 4. حزم التنفيذ

| الحزمة | المحتوى | بوابة الخروج |
|---|---|---|
| P0.0 | خط الأساس، الأسرار، الصحة، الأخطاء، CI | API يبنى، لا سر في المستودع، Health endpoints موثقة |
| P0.1 | الاتصال والدخول والجلسة والنطاق | مستخدم لا يرى بيانات خارج نطاقه |
| P0.2 | الصلاحيات والكتالوج والقوائم المرجعية | القائمة والأوامر من الكتالوج وAPI يمنع غير المصرح |
| P0.3 | العملات والحسابات والمراكز والبنوك والصناديق والأطراف | كل Lookup مرشح حسب الشركة والفرع والنشاط |
| P0.4 | محرك السندات والترقيم والاعتماد | حالات منفصلة، منع التكرار، فصل واجبات |
| P0.5 | سند القبض الكامل | قيد واحد متوازن، بحث وطباعة وتدقيق وفك ترحيل مضبوط |
| P0.6 | اختبارات القبول والإطلاق التجريبي | لا عيب حرج، استعادة النسخة الاحتياطية مجربة، قبول المستخدم |

## 5. الدفعة التنفيذية الأولى — P0.0

### بدأ التنفيذ

- إزالة نص الاتصال السري من `appsettings.json`.
- جعل نص الاتصال يأتي من متغير بيئة أو User Secrets.
- إلغاء اكتشاف إصدار MySQL عند الإقلاع واستبداله بإصدار مضبوط لتقليل اعتماد بدء الخدمة على اتصال قاعدة البيانات.
- إضافة معالج مركزي للاستثناءات يعيد `ProblemDetails` مع `traceId` دون تسريب التفاصيل في الإنتاج.
- إضافة فحص حياة للخدمة `/health/live`.
- إضافة فحص جاهزية قاعدة البيانات `/health/ready`.
- تقييد CORS وفق قائمة أصول مضبوطة بدلاً من السماح العام في الإنتاج.
- تفعيل إعادة المحاولة المؤقتة لاتصال MySQL.
- إعداد بناء آلي للمشاريع الرئيسية على GitHub Actions.

### ما يزال مطلوباً لإغلاق P0.0

- تشغيل البناء الآلي ومعالجة أي أخطاء تظهر.
- تدوير كلمة مرور قاعدة البيانات التي سبق وجودها في تاريخ المستودع.
- توثيق إعداد البيئة المحلية وبيئة الاختبار.
- إضافة اختبارات دخان للـ API وفحوصات الصحة.
- جرد Migrations ومقارنة القاعدة الحالية بالنموذج.

## 7. تعريف الإنجاز

لا تغلق أي شاشة أو خدمة إلا بعد تحقق جميع البنود المناسبة لها:

- مخطط بيانات وMigration آمنان.
- API وتحقيق Server-side validation.
- صلاحيات ونطاق بيانات في الخادم والواجهة.
- سجل تدقيق للعمليات الحساسة.
- رسائل أخطاء عربية مفهومة مع رقم تتبع.
- اختبارات وحدة وتكامل وصلاحيات.
- بحث وترقيم صفحات للبيانات الكبيرة.
- عدم وجود استعلامات متكررة أو تحميل كامل غير مبرر.
- توثيق مختصر وقبول المستخدم المسؤول.

## 8. أهداف الأداء الأولية

- فتح شاشة معتادة: أقل من ثانيتين عند p95.
- أول نتائج Lookup: أقل من 500 مللي ثانية عند p95.
- بحث سند مفهرس: أقل من ثانية عند p95.
- حفظ مسودة سند قبض: أقل من 1.5 ثانية عند p95.
- ترحيل سند قبض وإنشاء القيد: أقل من ثانيتين عند p95 في بيئة الاختبار المستهدفة.

تثبت القيم النهائية بعد قياس أجهزة وشبكة وقاعدة بيانات التشغيل الفعلية.

## 9. بوابة قبول سند القبض

- كل حقل ظاهر يحفظ ويستعاد.
- الرقم فريد داخل نطاق الترقيم المعتمد.
- لا حفظ أو ترحيل في فترة مغلقة.
- الحسابات نشطة وحركية ومسموحة.
- العملة والسعر والمبالغ المحلية صحيحة.
- المراجعة والاعتماد يطبقان الصلاحيات وفصل الواجبات.
- الترحيل Idempotent وينشئ قيداً واحداً متوازناً.
- لا تعديل أو حذف مباشر بعد الترحيل.
- فك الترحيل يحتاج صلاحية وسبباً وفترة مفتوحة.
- البحث والطباعة والسجل الزمني واستعراض القيد تعمل.
- التدقيق يحفظ المستخدم والتاريخ والقيمة القديمة والجديدة.
- اختبارات الأداء والتزامن والنسخ الاحتياطي والاستعادة ناجحة.
