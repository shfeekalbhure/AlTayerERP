# مراجعة API

يوجد 53 Controller. المصادقة تطبق Middleware عامًا لمسارات `/api` ثم صلاحيات شاشة داخل عدد كبير من Controllers؛ هذا منفذ جزئيًا ويحتاج اختبارات سلبية 401/403.

## حالة Endpoints

| التصنيف | النتيجة |
|---|---|
| مكتملة شكليًا | Auth، الجلسات، المراجع المحاسبية، السندات، طلب الصرف، تقارير الجوال |
| جزئية | القوائم كثيرة بلا Pagination قياسي؛ مثال طلبات الصرف يعيد حتى 500 صفًا فقط |
| غير قابلة للتحقق | توافق DTOs على قاعدة نظيفة ونتائج UAT الفعلية |
| غير محمية بالصفة مباشرة | عدة Controllers لا تحمل `[Authorize]`، لكنها تقع خلف Middleware العام؛ ليست ثغرة وصول مثبتة دون اختبار طلب حي |

## عيوب مؤكدة

- لا يوجد Global Exception Handler مخصص في `Program.cs`؛ التوحيد والـcorrelation logging غير مثبتين.
- `PaymentRequestsController.List` يستخدم `Take(500)` بلا `page/pageSize/total`.
- دورة طلب الصرف لا تسجل فاصلًا حتميًا بين المراجع والمعتمد.

العيوب: AT-007، AT-008، AT-010.
