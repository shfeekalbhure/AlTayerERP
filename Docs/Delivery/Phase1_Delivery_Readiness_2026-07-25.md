# جاهزية تسليم المرحلة الأولى — AlTayerERP

**التاريخ:** 25 يوليو 2026  
**فرع العمل:** `agent/unified-phase1-screens` فقط  
**قاعدة البيانات المعتمدة:** `altayer_erp_db` فقط  
**حالة الدمج:** لا دمج إلى `main` أو `master`.

## ملخص الحالة

الحزمة جاهزة **لتجربة القبول على نسخة اختبار**، وليست معتمدة بعد كتسليم نهائي للإنتاج. لا يوجد حذف بيانات أو إنشاء قاعدة جديدة ضمن هذه الحزمة.

## ما تم التحقق منه

- الهيكل يتكون من `Core` و`Infrastructure` و`API` و`Desktop`، وتعمل واجهة سطح المكتب عبر API.
- مسار البناء في GitHub Actions يستعيد ويبني API وDesktop بإصدار Release على Windows و.NET 8، من دون تشغيل SQL أو Migration على الإنتاج.
- آخر Build رسمي متاح للفرع قبل التعديلات المحلية الحالية: ناجح للـ API وDesktop.
- سياسة الصلاحيات Default Deny موجودة في `ScreenAuthorizationService`، وتتحقق العمليات الحساسة خادميًا.
- طلب الصرف يمنع إنشاء أكثر من سند صرف مرتبط عند التنفيذ المتزامن، ويحدث ربط الطلب والسقف المالي ضمن معاملة واحدة.
- شاشة سند الصرف أعيد تنظيمها بالقالب RTL الموحد، وشاشة الدول عولج قص حقولها السفلية.
- لا توجد مؤشرات `TODO` أو `NotImplementedException` في ملفات المصدر والفحوصات النصية.

## عناصر القبول الإلزامية قبل اعتماد التسليم النهائي

1. رفع الالتزامات المحلية الحالية إلى الفرع وتشغيل GitHub Actions عليها؛ لا يكفي نجاح Build سابق لالتزام مختلف.
2. تنفيذ اختبارات القبول الموثقة في `Tests/` على نسخة اختبار محدثة من `altayer_erp_db`، وبالأخص:
   - `Part31_Vouchers_And_PaymentRequest_Acceptance.md`
   - `InstitutionalGeographicScreens_FinalAcceptance.md`
   - `VoucherPostingEngine_Acceptance.md`
   - `FrmMain_Permission_FailClosed_And_Reports_Acceptance.md`
3. التحقق بحسابات أدوار مختلفة من رفض API عند غياب View/Add/Edit/Approve/Unapprove/Delete.
4. اختبار إنشاء وحفظ ومراجعة واعتماد وترحيل وفك ترحيل سندات القبض والصرف والقيود، ضمن سنة وفترة مفتوحتين ثم مغلقتين.
5. اختبار طلب الصرف من المسودة حتى إنشاء سند الصرف المرتبط، بما في ذلك تجاوز السقف ومحاولة الإنشاء المكرر.
6. اعتماد مالك المشروع بعد الاختبار المحلي؛ لا يفتح طلب دمج إلى `master` قبل هذا القبول.

## القيود المعروفة

- لا توجد مشاريع Unit/Integration Tests قابلة للتشغيل؛ الاختبارات الحالية سيناريوهات قبول موثقة.
- بيئة المراجعة الحالية لا تتضمن .NET SDK، لذلك لا يمكن تنفيذ Build محلي جديد فيها.
- ملفات SQL وترقيات قاعدة البيانات لا تطبق تلقائيًا من CI ويجب تنفيذها فقط على نسخة اختبار بعد نسخة احتياطية.

## قرار التسليم

**الحالة الحالية: جاهز للتجربة والقبول المشروط.**  
يتحول إلى **جاهز للتسليم النهائي** بعد نجاح GitHub Actions للالتزامات الحالية، واجتياز سيناريوهات القبول على `altayer_erp_db`، واعتماد مالك المشروع.
